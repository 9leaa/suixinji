# 按名称和上下文完成任务

用户不需要任务 ID 或编号。名称、同义表达及最近展示/操作的任务上下文用于召回和语义判定，匹配后更新原卡为 done。状态仍只有 todo / done。

## 处理方式
1. 完成表达进入任务指代解析；疑问、否定、条件表达不进入此写入路径。
2. 对有权访问的任务进行多路召回，补充最近任务清单/操作上下文和同名任务全部轮次（包含 done）。
3. 模型通过严格 Schema 返回明确匹配、歧义、未找到或非整体完成。候选外 ID 禁止写入。
4. 唯一匹配时保存目标 ID 和版本，再执行原卡更新；歧义时列出候选，可按名称补充或编号选择。
5. 保存原文、解析证据和版本变化。同一消息重试复用原目标；名称操作不替换此前显示的编号映射。

## 验证
101 项相关自动测试通过。deepseek-flash 在隔离 SQLite 的 6 张构造卡片上执行 8 次请求，7 项检查通过：
- 合同打印好了：打印采购合同变 done，无需先列清单。
- 刚才那个发送任务完成了：发送变 done，审核仍 todo。
- 清洁检查完成了：本周、下周存在歧义，两张都不修改。
- 任务1请标记完成：只修改澄清清单对应的一轮。
- 本周的清洁检查完成了：按自然语言指定本周。
- 项目报告初稿写完了：提交项目报告仍 todo。
- 自行车保养完成了：未找到已有卡片，不新建任务。

首次实测各条处理正常，但报告脚本对生成器使用 len 导致收尾失败；修正为 list 后在新隔离库重跑，完整报告成功保存。

## 范围
此入口负责完成已有任务。未匹配、局部进展的输入返回说明，不由此入口创建新记忆或更新进度描述。
上下文目前来自同会话最近展示的任务清单或任务操作，不是任意历史聊天全文。
语义识别依赖模型，定向检查不代表所有表达均已覆盖；多卡逐项写入，不保证整批事务原子性。
