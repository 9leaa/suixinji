## 实际处理链路

| 环节 | 技术实现 | 直白解释 |
|---|---|---|
| 接收消息 | 原 Note 持久化、原任务/偏好抽取协议保留 | 先存原话；待办与偏好继续走原流程 |
| 两类即时抽取 | 独立自然语言抽取调用，提供同空间相关记忆与近期事实；证据必须是当前原文连续片段 | 结合前文弄清说的是谁，但不把旧话重复记一遍 |
| 即时写入 | 追加事实、来源版本、类型、时间证据、指代状态和关联依据 | 原话留底；还没整理也能查询 |
| 整理触发 | 上海时间每日 03:00 后一次，或某类未处理事实达到 30 条；也可手动触发 | 每天整理；消息多时提前整理 |
| 整理规划 | Flash 模型读相关记忆/原文，再选择整理工具 | 模型先查清证据，再决定合并、更新还是询问 |
| 方案校验 | 用真实写入函数在回滚事务内预检，再独立核对语义证据 | 先检查参数能不能执行，再检查内容对不对 |
| 提交 | 同空间租约；来源和目标版本检查；事务提交 | 一次整理全成功或全不提交，不覆盖并发的用户修改 |
| 查询 | 语义/情景可联合召回，保留事实、卡片、归纳标签和来源 | 查当前情况时，也能看到支持它的事件 |
| 用户检查 | 控制台展示问题、原文、归纳时间、修改版本、审批记录 | 用户能查依据、改错、否定归纳和审批删除 |

代码入口：`memory/fact_extraction.py`、`memory/fact_agent.py`、
`memory/fact_memory.py`。数据复用既有 `memory_workflow_state` 事务存储：
PostgreSQL 存 JSON 状态，本地单测使用 SQLite。未建立固定的“职业、公司、地址”等业务槽位。

## 数据层次

- **事实 `fm_fact`**：原文及证据片段、note ID、来源版本、语义/情景类型、陈述时间、
  不精确时间证据、实体线索、指代状态、访问范围、处理状态。ID 保证重试幂等；
  不用 ID、名字相似或向量相似度直接判定是否同一个人/事件。
- **整理卡 `fm_card`**：较粗的对象或事件自然语言、来源事实 ID、类型、
  `stated/inferred`、整理/归纳时间、审阅状态、版本、访问范围。
  同一对象的多个方面可放在一张卡；同名不同主体和不同次事件要区分。
- **过程数据**：版本 `fm_version`、关系 `fm_relation`、待确认问题 `fm_question`、
  运行和完整工具观察 `fm_run`、删除审批 `fm_delete`、遗忘标记 `fm_tombstone`、
  日程 `fm_schedule`、疑问/归纳汇总 `fm_digest`。
- **权限**：派生卡继承全部来源中最严格的访问范围；不同所有者不可自动合并。
  召回先限定空间、有效状态及访问权限。来源变更/被遗忘后，依赖卡失效。
  来源版本在抽取前检查：即使改后的笔记没有可提取信息，也使旧事实、依赖卡和
  旧证据上的待确认问题失效。该检查不依赖偏好功能是否开启。

## 整理工具

| 工具 | 什么时候用 | 操作边界 |
|---|---|---|
| `search_memory` | 找相关事实或卡片 | 召回只是候选，不证明同一主体 |
| `inspect_memory` | 核查卡片及原始依据 | 只能引用本次已查看的有效证据 |
| `create` | 新对象、新事件或新归纳 | 陈述与推断分别建卡 |
| `add_evidence` | 新来源支持同一内容 | 新增实质细节须同时刷新完整正文 |
| `revise` | 同一对象变化、纠错、同次事件补充 | 保留仍成立的旧信息和版本 |
| `merge` | 已有卡重复表达同一对象/事件 | 不跨类型、不混陈述与归纳 |
| `split` | 旧卡混入多个主体/事件 | 每个输出都有来源 |
| `link` | 事实↔事实、事实↔卡、卡↔卡有关联 | 关联不等于合并 |
| `resolve_reference` | 上下文足以消解指代 | 保存被解析事实、依据和解释 |
| `defer` | 主体、时间或冲突仍无法确定 | 保留事实并生成待确认问题 |
| `retract` | 派生结论失去支持 | 撤回派生卡，不删除原始事实 |

这些写操作组成 `propose_memory_changes` 方案，由程序统一校验和事务提交，
并不是模型任意直写数据库。用户遗忘走独立的“预览→选择→批准”操作，
不由整理模型擅自执行。

## 时间、归纳与疑问

晚记录的历史不能覆盖较新生效的状态；纠错不被解释成现实变化。
不精确年份或日期保留原始表达，不被转为 1970 年的 Unix 秒时间。
上下文包含多个可能主体时，“最近提到”本身不够证明指代。

从多次事件归纳的卡始终标为 `inferred`，保留生成时间、证据及时间/场景限制。
用户确认后仍显示归纳来源，不冒充用户原话；用户编辑后锁定内容，
自动整理不能覆盖。被否定的归纳不能用相同证据静默重建。

回答疑问会新增一条带原问题及关联事实的补充证据，并重新开放相关事实供整理。
手动整理结束直接返回全部待确认问题和待审归纳；每日整理完成尝试通过
已有回复路由发送汇总，没有回复路由时仍可在控制台查看。
阈值整理不会强制即时打扰用户。每日无新事实但有未解决疑问时仍生成汇总。
超过单批 60 条时，尾批完成前不标记当日处理完毕。

## 相关记忆召回

三阶段共用 `fact_retrieval.rank`：先按空间、有效状态和权限过滤，再计算词面与
语义向量相似度，融合权重为 0.35 / 0.65。不维护特定测试例子的同义词词典。
向量按 provider 端点、模型、维度和正文缓存；检索记录 `fm_retrieval` 保留各路
分数与最终 ID。提供方不可用时会标记降级为词面检索。

- 即时抽取：相关前 12 条 + 最近 8 条事实，排除当前消息，并保存实际上下文 ID。
- 整理：每条新事实找前 8 条，补证的显式关联必取；卡片展开来源，最多再读取 3 次。
- 查询：普通搜索、历史工具、最近事件列表均读新存储。历史问答综合有效事实和
  当前卡，不把旧存储查不到新 ID 当成无记录。事件列表不把卡和它的来源重复计数。

向量相似只是召回依据，主体关联仍由原文和上下文核实。删除预览同样是候选列表，
必须由用户选择审批；相近对象不能因为向量接近而直接删除。
与陈述卡同文、同类型且确为该卡来源的事实不重复占用召回名额；保留卡，
再展开来源。独立事件即使文本相同也不因此合并。删除预览仍展示可逐项选择的来源事实。
整理遗漏某条新证据时，反馈具体缺失 ID 和内容，要求补全原方案，而不是只返回笼统错误。
模型拿到的 Note、补充证据和共享原文会屏蔽已遗忘跨度，原 Note 存储不变。
即使同一笔记还剩另一条有效事实，也不能用它的完整原文重建已删除的内容。

独立测试发现部分现有 Key 返回 HTTP 402。现在密钥池会将该 Key 冷却 30 分钟，
并尝试另一枚已配置可用 Key。若仍失败，事实抽取记为失败待重试，不能静默写成空；
事实综合回答明确显示降级，并列出完整去重证据，不以前三条片段伪装完整答案。

## 控制台与测试

统一入口为 `http://127.0.0.1:18080/console` 的“记忆整理与审批”按钮：
复用当前令牌和空间，不把令牌写入 URL 或浏览器持久存储。支持手动整理、
补充问题、筛选、查看来源、确认/修改/否定、版本历史、主题删除预览、
逐条/全选审批。删除记忆保留 Note；遗忘标记阻止同一来源再次被提取。
疑问和卡片均可展开可读的原文片段、记录时间，再查看完整来源详情。
每日两类整理都结束后合并发送一次疑问/归纳摘要；手动整理结束立即显示。

命令入口包括 `/memory facts consolidate [semantic|episodic]`、
`questions`、`answer <问题ID> <说明>`、`forget <主题>`、
`approve-delete <申请ID> <ID1,ID2>`。控制台中的明确自然语言
“删除……相关的记忆”也只创建审批预览。

独立测试空间统一使用 `fmeval_` 前缀，自动调度不处理这些空间，
由评测控制整理边界。真实模型测试、注入事实的结构测试、UI 操作测试分别统计。
正确率不能用结构断言的通过数抬高，也不能把 Note 回退答对等同于记忆整理成功。
每轮固定数据和预期，保留首次、失败项复测、最终整轮复验以及各自源码哈希；
模型自动评分和助手证据复核单独标识，不称为人类审核。

本地隔离服务包括 API、adaptive worker、scheduler 和 outbox relay。缺少 relay
