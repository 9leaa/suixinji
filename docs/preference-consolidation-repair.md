# 偏好整理与关联修补

分支：`codex/preference-consolidation-repair`。基础版本：远程 main 的 `d2fcf6f`（偏好卡片与消息流程控制台整合）。仅改变偏好卡片的处理，其他类型作为原文上下文只读，不自动改写分类。

## 本次行为

1. 偏好关联直接使用已有混合检索返回的排序，不再经过旧 `preference_signature` 身份规则过滤。候选仍按空间、账号、主体和可用状态隔离。
2. 候选不直接成为关联。模型区分 `equivalent/related/unrelated/uncertain` 并说明依据；只有前两类写入当前卡片的出向列表，不自动反向写入。查询可以独立召回后来创建的卡片，无需补造反向边。
3. 整理先读取仍可用的笔记原文和消息时间，补充相关事件、语义记忆的原文。模型必须逐条审核当前卡片的有效细节；已判定有支持的态度再经过一次聚焦的证据核验，防止把行为、能力或习惯等同于好恶。
4. 支持去重、明确更正、明确变化、无依据断言隔离、歧义 pending、同义对象归并。不同条件或态度不得按重复删除；状态改变保留 history；总体与例外并存。跨卡片归并只接受同主体、同账号、确认同义且双方有来源的对象；咖啡与拿铁不是同义对象。
5. 归并将来源、细节和历史迁到保留卡片，旧卡片归档并保留重定向；使用旧名称写入时仍定位到保留卡片。现有入向关联随之改目标，不新增反向关联。超容量时不强行删事实。
6. PostgreSQL 使用同一事务更新所有涉及的卡片、版本、作业和待反馈队列，锁定并比较卡片版本、核验原文是否被修改/删除及来源是否遗忘。SQLite 卡片事务同样原子提交，文件原文在提交前复核；文件与 SQLite 不属于同一数据库事务。
7. 无依据/冲突细节成为 `pending_review`，保留审计证据；问答材料明确标记其未确认，不能当成既定偏好。已删除或不可用的证据不暴露给问答。反馈包含原文及原因，并纳入问题数据集；疑似问题仍需人工确认才可作为评测标准答案。
8. 保留原数量、24 小时触发；补齐无新变更卡片的 7 天关联刷新及强制整理。整理本身不增加业务变更计数。

设计参考 Hindsight 的“按实体/具体方面归并、依据原文保留历史、聚焦核验而非相似度直接合并”。本实现不是 Hindsight 的原样移植；模型语义判断仍可能出错。

## 流程展示与手动入口

控制台新增命令：

```text
/memory consolidate preferences
```

在当前控制台空间执行。展示：定期整理 → 候选检索 → 原文与相关记忆 → 证据审核与操作计划 → 独立态度核验 → 校验并原子保存。模型输入输出、操作依据和结果沿用现有真实调用追踪。

CLI：

```bash
python -m scripts.memory_workflow --space <space_id> consolidate
```

CLI 没有控制台 trace 上下文时仍保存整理审计记录，但不会自动创建控制台页面记录。无需新增数据库迁移；服务重启后加载代码。本次没有重启现有业务服务，也没有对用户原学习案例所在空间直接执行新整理。

## 2026-10-19：自动处理明确的提取错误

将审核结果分为两类：`unsupported` 表示原文含义清楚但无法支持已存态度，细节自动转 `retracted`（撤销），原笔记与旧判断保留供审计，不新建用户待审核；`uncertain` 或无法消解的冲突才进入 `pending_review`。撤销不等于相反态度，也不自动迁移成其他记忆类型。

整理会重新审核旧的 `pending_review` 细节；确认提取错误后，通过事务内 outbox 保存质量案例，并关闭对应的 `consolidation_review` 待审核，取消尚未发送的旧提醒，不追加确认通知。其他来源的待审核不会被一并关闭。质量案例保留整理前后细节和原文证据，仍需人工确认才作为标注数据集导出。

撤销细节不参与有效偏好及问答偏好证据，不计入卡片总体态度。原笔记保持可检索；卡片版本和整理计划保留变更记录。关联算法、其他记忆类型的分类规则本次不改。

本次验证：83 项相关测试通过。服务重启后，在原学习评测空间 `sample30-20261018-1905-d18_c01` 通过控制台再次执行整理（trace `84c6d78bd6ab4556b17bdf87c7a18dcc`）：5 条旧待审核偏好全部自动撤销，关闭对应 5 个待审核，新增 5 个质量案例，卡片版本 3→4，9 条原笔记逐字比对未变化；待审核总数 7→2，剩余两项属于此前提取阶段的指代问题。13 个服务进程存活，18000 健康接口与 18080 控制台返回 200。

## 后续口径调整：保留行为与习惯偏好

用户明确要求保留从“经常做、能坚持、看不进”等行为中推断喜欢/不喜欢的能力。提取、整理、独立核验改用共同的 `PREFERENCE_INFERENCE_POLICY`，取消必须直接表达好恶的限制；保留主体、条件、原文依据，推断需在描述中明示。孤立行为、被迫执行、明确否认好恶仍不能直接作为正向倾向。问答同步区分“明确表达”与“从行为推断”。

原学习案例五条撤销细节经真实模型按新规则核验全部 supported，使用有版本检查的事务恢复 active（版本 4→5），保留旧撤销审计，描述注明行为推断，原笔记未修改；对应五条自动撤销质量案例改标 normal，不作为错误标注导出。此为用户要求下的定向恢复，不自动恢复已遗忘或已删除的资料，也没有全库重跑。
