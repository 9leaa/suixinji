# 全量任务清单与自然语言编号完成

## 用户使用方式

直接说“当前还有哪些未完成任务？列举出来。”，返回当前空间、当前用户可访问的全部已保存 todo 任务及总数，每项带编号、标题、轮次和当前描述。直接说“任务1，任务5请标记完成”，按最近一次清单中的编号更新原卡为 done，不新建任务。

## 实现

- memory/task_commands.py：受控的自然语言入口；全句识别列清单或编号完成，疑问、否定、引用不会触发写入。不依赖模型选择任务，支持阿拉伯数字、中文数字及逗号/顿号/和连接。
- 清单用 task_cards.records 的游标分页遍历，直到取完。绕过原有 Top-K、候选上限和回答证据裁剪；仅列 todo，应用空间、所有者、权限、有效期限制。等待前置消息的记忆处理屏障；超时不宣称清单完整。
- 快照持久化为编号→memory_id/current_version；租户、用户、空间、会话隔离。完成后不重新排列旧清单；用户重新请求列表才产生新编号。
- 操作前验证全部编号和目标权限、版本；非法编号、目标已变更或删除时不猜测替代目标。已 done 不重复写。写入使用已有任务版本校验机制，保留修改前版本；完成描述是用户确认该任务已完成，原描述和要求可在旧版本及来源追溯。
- 同一 message_id 的重试绑定原操作快照，即使其间重新列出，也不会按新编号修改其他任务。操作中若某个写入发生并发冲突，逐项准确报告成功/失败，不声称全部成功；多任务写入不是一个全有或全无事务。
- 原始完成指令、列表快照 ID、显示编号随任务来源保存，命令操作记录持久化。task_status 只使用 todo/done。
- 接入公共 answer_question、结构化问答入口、控制台自然消息、飞书自然消息、本地和分布式查询执行器；补齐本地任务写入的用户身份传递。飞书长文本按 UTF-8 字节分段发送，不省略任务；测试使用假发送端，未实际发送飞书消息。

## 验证

本地 90 项相关测试通过，包含 125 张 todo 全量输出（跨越原 100 条数据库查询上限）、编号 1/5 绑定、幂等、重新列出后的旧请求重试、用户和会话隔离、越界/过期/删除、并发冲突反馈、控制台处理入口、飞书消息路由和长文本完整拼接。Ruff 与 git diff --check 通过。

另外通过 scripts/check_task_inventory_flow.py，从既有真实模型重放结果复制 6 张 todo 卡到独立 SQLite，通过实际控制台路由和公开问答/写入函数完成：6 项全部返回→指定原编号 1/5 完成→原卡数量仍为 6→剩余 todo 为 4。该功能本身不调用模型，返回内容来自实际数据库，不是模型编造示例。

实际完成回执：

```
任务 1：向客户发送演示文稿 — 已标记完成（done）。
任务 5：递交签证材料 — 已标记完成（done）。
```

## 范围

功能受现有 SUIXINJI_TASK_CARDS_ENABLED 开关控制。完整是指已存入记忆库、当前用户可访问的 todo；尚未抽取或被错误标记的内容不能凭清单接口自动修复。T4 审核完成漏抽问题仍存在，因此本次复制的审核卡仍出现在 todo 清单中；没有偷偷修复测试数据。

不支持在同一句中混合执行完成、取消、删除等多种操作，也不支持根据猜测解析没有当前清单的编号。重新列出后按新清单编号操作。未部署、未修改生产数据、未跑完整 100 场景数据集；未做实际 PostgreSQL/浏览器/飞书端到端验收。
